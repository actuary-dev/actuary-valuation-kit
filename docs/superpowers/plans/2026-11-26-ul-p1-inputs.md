# UL P1: inputs and contracts — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans to implement
> this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not use
> Claude subagents (the Agent tool); work inline.

**Goal:** Everything UNIT_LINKED needs before its projection formulas exist: input contracts
(policy table and fund holdings table), new public formats, the fund universe and product
tables, regulatory caps, validation, vectorised preparation into fund-slot fields, a
registered skeleton product, demo inputs, and documentation.

**Architecture:** A new package `avk.products.unit_linked`. Policy-level rows come from
`policies_ul`; fund-level rows from the companion table `policy_funds_ul`, which the run
layer reads through a new product-generic factory hook and the adapter pivots into
`Fund_k_*` fields (k = 1..5). All tables are declared as bindings on the skeleton product
class (precedent: `Term.support`) so `avk check` validates every input now, before the P2
formulas read them.

**Tech stack:** Python 3.13, polars, numpy, pydantic, pytest, uv.

**Spec:** `docs/superpowers/specs/2026-11-26-unit-linked-product-design.md` (sections 3,
5.1–5.4, 5.7, 5.8). Source material: `C:\avkwt\_ref\` (read-only, never copy into the repo).

Prepared model-point fields (the adapter's output; P2a formulas read `self.policy.<name>`):

- Policy: Variant_Id, Regime_Id, Duration_in_Months, Age_at_Entry, Gender_Code (0 M, 1 F, 2 T), Smoker_Code (0 NS, 1 S), Charge_Column (= 2 x Gender_Code + Smoker_Code), Distribution_Channel, Policy_Term, Premium_Payment_Term, Premium_Frequency (0 single), Annualised_Premium, Instalment_Premium (AP / frequency; the single premium when single), Instalments_Payable (frequency x PPT; 1 when single), Sum_Assured, EMR, Flat_Extra, Flat_Extra_Term_Months, Policy_Status, Paid_Up_Sum_Assured, Premiums_Paid_To_Date, Instalments_Paid, PAC_To_Date, Admin_To_Date, MC_To_Date, GC_To_Date, Loyalty_To_Date, PW_To_Date, PW_Current_Year, PW_Previous_Year, FV_Sum_Current_Year, Disc_Charge_Paid.
- Variant features: `V_<field>` for every `ul_variants` field except variant_id/regime_id (e.g. V_death_benefit_type, V_lock_in_months).
- Regime: R_dpf_min_rate, R_dpf_fmc_max, R_caps_apply.
- DPF fund: DPF_Value (status 1 opening value, else 0), DPF_FMC, DPF_Alpha, `DPF_W_<asset>`.
- Slots k = 1..5: Fund_k_Present {0,1}, Fund_k_Fund_Index (position in `ul_funds` keys, -1 when empty), Fund_k_Allocation, Fund_k_Value (Units x unit_price), Fund_k_FMC, Fund_k_Alpha, `Fund_k_W_<asset>`, Fund_k_Premiums_Allocated, Fund_k_Guaranteed_Price. Empty slots hold zeros (Present 0). Slots are filled in the order of the fund's position in `ul_funds` keys. A status-1 policy has every slot empty; its DPF holding sets DPF_Value.

Factory hook (product-generic, existing factories unaffected):

```python
class ProductFactory(ABC):
    companion_tables: tuple[str, ...] = ()  # logical names of extra policy-level tables

    # Factories with companions implement:
    def companion_adapter(
        self, tables: Mapping[str, Table], companions: Mapping[str, pl.DataFrame]
    ) -> ModelPointAdapter: ...
```

The run layer calls `companion_adapter` instead of `model_point_adapter` when
`companion_tables` is non-empty, after reading each companion once with
`inputs.read(name)` and validating it with the factory's validator
(`validate_companions(policies, companions, valuation_date) -> list[Issue]`).
